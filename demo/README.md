# GoNovel 功能展示（示例库）

> 本目录是**上传的示例库**，仅用于提交与展示：预置一组干净、可直接复制粘贴的 `.gnd` 示例，
> 使用者可以在自己的 Obsidian 仓库里照抄语法，验收者可以据此对照预期现象。
> 本地验收请去 `test-local/`（带 `-local` 字样的本地目录），两处内容由同一个脚本生成、内容完全一致。
>
> **文档定位**：示例库操作手册 ｜ **版本**：v0.8.0（随插件）
> **同步铁律**：本目录的 `.gnd` **由脚本生成**，改样例必须改 `scripts/demo.mjs` 再重新生成；手改会被覆盖。

> **项目速记**：
> - `go-novel`：Obsidian 小说管理插件（主页管理视图 + 小说项目主页管理视图）；
> - 插件只管 `.gnd`：`.gnd` 注册为 markdown，编辑／阅读／实时预览交给 Obsidian 原生，vault 里的 `.md` 不归插件管理；
> - 插件**不代管 `.gnd` 的打开**：`.gnd` 从任何文件入口（原生文件列表 / 工作台文件树）打开都是 Obsidian 原生 markdown；只有两个视图由插件自己打开 —— 左侧 Ribbon 的「gn 工作台」打开工作台（工作台 ① 进管理视图），点管理卡片打开小说项目主页管理看板；
> - 完整功能见 [README](../README.md)。

## 预置内容（14 个 .gnd，按分类）

已预置 14 个示例文档，与本地验收套件一一对应：

- **干净样本**（3 个）：预期无 error / warning
  - `小说项目/主页.gnd` —— home，演示多级导入 + 字段展示；
  - `小说项目/大宋仙途/大宋仙途.gnd` —— project，4 个变量 + `gnd_image` 封面；
  - `小说项目/都市悬疑/都市悬疑.gnd` —— project，3 个变量 + `gnd_image` 封面。
- **错例样本**（9 个）：故意各触发一类诊断
  - `01-gnd类型非法.gnd` —— `gnd_type: xxx`；
  - `02-未知关键字.gnd` —— `**SUMMARY**` 未定义 + `**SELECT**` 重复出现；
  - `03-导入路径错误.gnd` —— 单级路径 + `..` 越界 + 目标不存在；
  - `04-变量问题.gnd` —— 空变量名 + `[作者]` 重复定义 + `gnd_image: ../越界.png`（封面路径非法）；
  - `05-字段缺失.gnd` —— 导入到 home 类型 + 被引用字段为空；
  - `06-缺少frontmatter.gnd` —— 整份文件没有 frontmatter；
  - `07-缺少gnd类型.gnd` —— 有 frontmatter 但缺 `gnd_type`；
  - `作品甲/作品甲.gnd` —— project，**故意不写 `[简介]`**（「字段为空」的对端），且 `gnd_image` 指向**不存在的图**（「封面缺失」的对端）；
  - `作品乙/作品乙.gnd` —— 故意写成 home，作为「导入类型错误」的对端。

## 诊断等级（三档）

级别只看**问题出在谁身上**，与严重程度无关，也不参与排序（面板按产生时间倒序）：

| 级别 | 含义 | 覆盖的错误类型 |
|---|---|---|
| `error` | **结构与声明写错** —— 必须改文件，且会让整块内容无法解析 | 缺少 frontmatter、`gnd_type` 缺失／非法、未知关键字、关键字重复、同级目录类型相同、读取失败、**封面组 `COVER_*` 统一 error**（封面路径非法／图片不存在／下载失败／链接 404／格式非法／解析失败／写盘失败） |
| `warning` | **取值、引用或登记失败** —— 文件能用，只是取值不理想、或指向／登记的东西不可用 | 空变量名、变量重复、导入路径错误、导入目标不存在、导入类型错误、文件不存在、主页类型错误 |
| `info` | **运行期信息** —— 扫描时观察到的数据缺失与运行日志 | 字段缺失（`**WHERE**` 取空）、运行日志 |

## 验收结果对照（登记态 × 诊断）

**前置规则**：debug **只认 `data.json` 里已登记的文件**，未登记的一律不出诊断；
`projectColors` 的键由插件按「已登记主页的 `**SELECT**` 导入」推导，不能手写不存在的作品。

按下表登记（即 `data.example.json` 的默认值）——主页卡 **3** 张，作品卡 **3** 张：

| 登记项 | 键 | 说明 |
|---|---|---|
| `homePaths` | `小说项目/主页.gnd` | 干净主页，看板出 2 张作品卡 |
| `homePaths` | `调试样例/03-导入路径错误.gnd` | 错例主页，看板出 0 张作品卡 |
| `homePaths` | `调试样例/05-字段缺失.gnd` | 错例主页，看板出 1 张作品卡 |
| `projectColors` | `大宋仙途` / `都市悬疑` / `作品甲` | 前两者来自主页，`作品甲` 来自 `05` |
| `imageCache` | （空仓库） | 网络封面图片缓存：`{ kind: "image-cache", items: [{url, hash, local, source, updated}] }`；样例封面都是库内路径，故 items 留空 |

调试框里应**恰好**出现这 7 行（行格式 `[级别] 错误类型:文件名`，同文件同类型多条在行尾计数）：

| 文件 | 级别 | 错误类型 | 条数 | 说明 |
|---|---|---|---|---|
| `03-导入路径错误.gnd` | warning | 导入路径错误 | 2 | 单级路径 + 含 `..` |
| `03-导入路径错误.gnd` | warning | 导入目标不存在 | 1 | `作品甲/不存在.gnd` |
| `03-导入路径错误.gnd` | error | 同级目录类型相同 | 1 | 与 `05` 同目录且都是 home |
| `05-字段缺失.gnd` | warning | 导入类型错误 | 1 | `作品乙` 是 home，不是 project |
| `05-字段缺失.gnd` | error | 同级目录类型相同 | 1 | 与 `03` 同目录且都是 home |
| `05-字段缺失.gnd` | info | 字段缺失 | 1 | `[简介]` 在 `作品甲` 中为空 |
| `作品甲.gnd` | warning | 封面图片不存在 | 1 | `gnd_image` 指向 `assets/cover/Gold-1x1-512x512.png`（不存在） |

> `作品甲` 能被诊断，是因为 `05` 导入了它 —— 它由此进入 `projectColors`，也就进入了诊断范围。
> 面板里这 7 行**自上而下是时间倒序**（最新在顶），与上表按文件归类的顺序不同。

未登记的错例（`01`／`02`／`04`／`06`／`07`／`作品乙`）**不出现在诊断里**。把它们也登记进 `homePaths` 后，可额外看到：

| 文件 | 登记后额外可见 |
|---|---|
| `01-gnd类型非法.gnd` | `[error] gnd_type 非法`（文件写错）+ `[warning] 主页类型错误`（登记为主页但类型非法） |
| `02-未知关键字.gnd` | `[error] 未知关键字` + `[error] 关键字重复` + `[error] 同级目录类型相同` |
| `04-变量问题.gnd` | `[warning] 主页类型错误` + `[warning] 空变量名` + `[warning] 变量重复` + `[warning] 封面路径非法` |
| `06-缺少frontmatter.gnd` | `[error] 缺少 frontmatter` + `[warning] 主页类型错误` |
| `07-缺少gnd类型.gnd` | `[error] gnd_type 缺失` + `[warning] 主页类型错误` |

> 「同目录唯一性」：同一目录下只允许一个 `home`、一个 `project`（一个目录 = 一个小说项目）。
> 冲突组内**每个文件各报一条 error** 并点名同组其它文件；`data` 与非法 `gnd_type` 不参与判定。

## 可复制示例（按主题分节）

**主页（home）：导入作品并展示字段**

```gnd
---
gnd_type: home
gnd_created: 2026-09-11
---

[欢迎词]
晚上好，写点什么吧

**SELECT**
> 大宋仙途/大宋仙途.gnd
> 都市悬疑/都市悬疑.gnd

**WHERE**
[作者]
[简介]
[状态]
```

命中：管理视图多出一张主页卡（标题为文件名 `主页`），看板里出现 **2** 张作品卡，每张只展示 `[作者] [简介] [状态]`。

变体：把 `> 大宋仙途/大宋仙途.gnd` 改成单级 `> 大宋仙途.gnd`，即命中 `[warning] 导入路径错误` —— 导入路径一律相对**当前文档所在目录**，且必须多级。

**作品（project）：变量块**

```gnd
---
gnd_type: project
gnd_created: 2026-09-11
---

[作者]
九心 # 主笔

[简介]
都市职场群像，三条线在同一个雨夜交汇。 # 简介

[状态]
存稿中 # 状态
```

命中：被主页 `**SELECT**` 导入后，看板作品卡按 `**WHERE**` 取到 `[作者] [简介] [状态]` 三段值。

规则：行尾 `#` 之后是注释，不进入变量值；空行或文件结束即关闭当前变量块；同名变量会拼接取值。

**作品封面（project 的 `gnd_image`）**

```gnd
---
gnd_type: project
gnd_created: 2026-09-11
gnd_image: assets/cover/Orange-4x3-667x500.png
---
```

命中：看板作品卡顶部渲染该图（铺满槽位、居中裁切）；本示例库两张干净作品卡指向 `assets/cover/Vermilion-2x3-500x750.png` 与 `assets/cover/Orange-4x3-667x500.png`。

规则：值是**相对 vault 根**的库内路径 —— 写 `assets/cover/Orange-4x3-667x500.png`，**不要写 vault 名**，也不要写盘符绝对路径；
含 `..` 或盘符一律判为非法、视作无封面。**仅 `project` 有效**，写在 home / data 里会被忽略。
图片不存在（或路径非法）时封面退回空槽（斜纹占位），**同时记一条 `error` 诊断**（封面组统一 error）—— 看板不中断，但调试框会提示；空槽里带「刷新」按钮，补回图片后点一下即可出图。
挂载点是声明封面那个 `project` 文件自己（不是引用它的 home），错误类型分别为 `封面图片不存在` / `封面路径非法`。
**封面槽空时槽内一律出现「刷新」按钮**（不限于网络封面——本地路径封面的图片不存在 / 被移走、未声明封面时同样有；缓存图加载失败也退回空槽并补上按钮）：网络封面点击后清失败记忆并重新下载，本地／未声明封面点击后重跑一次解析（图片被补回来即出图）。**刷新仍失败会给一条 ⚠ 提示，并在调试框留一条 `warning` 级运行日志**（后台自动下载失败不打扰）。

**错例：三类导入错误一次命中**

```gnd
---
gnd_type: home
gnd_created: 2026-09-12
---

**SELECT**
> 单级.gnd
> ../越界.gnd
> 作品甲/不存在.gnd

**WHERE**
[作者]
[简介]
```

命中（登记该文件后）：`[warning] 导入路径错误` ‥‥ 2、`[warning] 导入目标不存在`、以及 `[error] 同级目录类型相同`（若同目录还有别的 home）。

**设置快照（`data.example.json`，逐字节可复制）**

```json
{
  "homePaths": [
    "小说项目/主页.gnd",
    "调试样例/03-导入路径错误.gnd",

  ],
  "managerNote": "点卡片进入小说项目主页；此处只负责登记与跳转。",
  "debugEnabled": true,
  "homeColors": {
    "小说项目/主页.gnd": "#C9F0D9",
    "调试样例/03-导入路径错误.gnd": "#B2F0E6",
    "调试样例/05-字段缺失.gnd": "#C9E8F5"
  },
  "projectColors": {

命中：覆盖到 `.obsidian/plugins/go-novel/data.json` 后重载插件，管理视图出现 **3** 张主页卡、看板共出 **3** 张作品卡，相邻卡片配色互不相同。

## 操作

1. **工程描述**：本示例库提供 GoNovel 全部 `.gnd` 语法样例与一组故意写错的诊断错例，适用于试用手感、照抄语法、复现诊断三类场景；不含任何个人数据。
2. **工程设置**：准备一个 **Obsidian 1.5+** 仓库，并构建插件产物（`main.js` / `manifest.json` / `styles.css`）。
3. **安装步骤**：把本目录的 `小说项目/`、`调试样例/` 与 `assets/` 复制进仓库根目录；在仓库内建 `.obsidian/plugins/go-novel/`，放入三个产物文件；将 `data.example.json` 复制为 `.obsidian/plugins/go-novel/data.json`；启动 Obsidian → 设置 → 第三方插件 → 关闭安全模式 → 启用 **GoNovel**。
4. **验收**：点左侧 Ribbon 的「gn 主页管理」打开管理视图（应见 3 张卡片）→ 点卡片打开看板（共 3 张作品卡：主页 2 张均有封面，`05` 那 1 张是**空槽**）→ 在设置里打开「调试信息开关」→ 在调试框点「刷新」，对照上表核对 7 行诊断。
5. **确认**：干净样本（`小说项目/` 三个文件）**不应**出现任何 error / warning；默认登记下调试框应**恰好**是上表那 7 行 —— `03` 出 3 条 warning + 1 条 error，`05` 出 1 条 warning + 1 条 error + 1 条 info，`作品甲` 出 1 条 warning；未登记的错例不出现在诊断里。
6. **清理**：删除仓库里的 `小说项目/`、`调试样例/` 与 `assets/` 三个目录（在工作台 ③ 里逐个删文件即可——**删掉目录里最后一个文件时，空目录会被自动一并清理**），再删掉 `.obsidian/plugins/go-novel/data.json`，即退回干净仓库。

## 开发

示例库由脚本生成，**不要手改本目录的 `.gnd`**（手改会被下次生成覆盖）：

```bash
# 在项目根目录执行

node scripts/demo.mjs                  # 按 scripts/demo.mjs 的定义重新生成 demo/
node scripts/demo.mjs --check          # 只比对 demo/ 与定义是否一致，不写盘
node scripts/demo.mjs --sync           # 生成 demo/ 后覆盖同步到 test-local/
node scripts/demo.mjs --sync --prune   # 同步时另删样例目录下的多余文件
node scripts/demo.mjs --target <dir>   # 指定同步目标（默认 test-local）
```

改样例的固定流程：改 `scripts/demo.mjs` 里的 `SAMPLES` / `DATA_JSON` → `node scripts/demo.mjs` → `node scripts/demo.mjs --check` 自检（含 README 内嵌快照一致性）→ `node scripts/demo.mjs --sync` 落到 `test-local/` 做真实环境验收。

封面素材由 `IMAGES` 定义、从项目根的 `assets/cover/` 复制（源缺失只提示、不报错）。`assets/` 整个目录在 `.gitignore` 里，
`--check` 不比对它 —— 你可以随意换成自己的图，`--sync` 也不会覆盖已存在的文件。

生成/自检时会跑两道守卫：`validateDataJson()` 校验 `homePaths` 与 `homeColors` 同序等长、相邻配色不同；
`validateCovers()` 校验每个 `gnd_image` 要么命中 `IMAGES`、要么登记在 `MISSING_COVERS` 里
（故意做封面错例的两个文件）—— 免得把写错的图片路径误当成「有意缺失的错例」。
